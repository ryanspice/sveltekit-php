### What each major artifact does

- .htaccess: Apache rewrites for SvelteKit routing, `__data.json` bridge, static file passthrough, and cache headers.
- index.php: `/` route entry for this build output; other routes are emitted as their own `.php` entries during prerender conversion.
- **data.php: Serves `**data.json` responses and provides hydration helpers for SSR HTML.
- \_\_action.php: Handles form actions for POST requests.
- \_app/immutable: Hashed JS/CSS bundles and runtime chunks for SvelteKit client.
- \_protected/: Namespaced copies of `+*.server.php` logic so runtime loaders/actions can be invoked safely.
- api/\*\*/index.php: PHP endpoints generated from `+server.php` routes and negotiation wrappers.
- router.php: PHP built-in server router and fallback rewrite logic (used when `.htaccess` is unavailable).
- **data.template.json: Runtime template for `**data.php` to match the current Kit payload shape.

## 4. Deployment Scenarios

### A) Subdomain root deployment

- Expected folder layout: `DocumentRoot=/var/www/app` and it contains the files from `build/`.
- Required adapter config values: `BASE_PATH=''`, `ADAPTER_MODE='php-static'` or `node-ssr`.
- Required Apache config: `.htaccess` from `build/` is honored in the docroot (AllowOverride All) or vhost-level rules replace it.
- Failure modes: 404 on non-root routes if rewrites are disabled; `__data.json` returning HTML if the rewrite bridge is missing; 502 if `node-ssr` sidecar is down.

Evidence: svelte.config.js:L4-L28, build/.htaccess:L1-L20, adapter/src/runtime/node-ssr-templates.ts:L484-L495, adapter/src/runtime/node-ssr-templates.ts:L500-L516

### B) Root domain deployment

- Expected folder layout: same as subdomain root; `DocumentRoot` points to the `build/` contents.
- Required adapter config values: `BASE_PATH=''`, `ADAPTER_MODE` set to desired mode.
- Required Apache config: `.htaccess` from `build/` or server-level rewrites that mirror it.
- Failure modes: asset 404s if the base path is set incorrectly; POST actions returning 405 if `__action.php` is not found or routed.

Evidence: svelte.config.js:L4-L28, build/.htaccess:L1-L20, build/\_\_action.php:L23-L49

### C) Subpath deployment (base path)

- Expected folder layout: `DocumentRoot=/var/www/html` with `build/` contents placed in `public_html/app/` (or equivalent).
- Required adapter config values: `BASE_PATH='/app'` and `kit.paths.base` set via config; rebuild required.
- Required Apache config: `.htaccess` should live inside the subpath folder; server must allow rewrites in that directory.
- Failure modes: broken asset links and client navigation if `BASE_PATH` does not match the actual subpath; `router.php` only strips base path when `SK_BASE_PATH` is set.
- Subpath rewrite note: if `.htaccess` is placed at the subpath root, rewrite targets are relative to that directory; if rules are moved to the vhost root, you may need `RewriteBase /app` or prefixed rewrite targets to keep `__data.json` and fallback rules working. **Inference:** This is standard Apache rewrite behavior; the adapter output does not include a `RewriteBase`.

Evidence: svelte.config.js:L4-L28, adapter/src/index.ts:L321-L468, build/router.php:L23-L33, adapter/src/runtime/node-ssr-templates.ts:L397-L399

### D) No `.htaccess` allowed (fallback router approach)

- Expected folder layout: same as root or subpath, but rely on a front-controller rule at the vhost level or PHP built-in server.
- Required adapter config values: same as above; set `SK_BASE_PATH` if the PHP router is used under a base path.
- Required Apache config: move `.htaccess` logic into the vhost config or use the PHP built-in server with `router.php`.
- Failure modes: without any rewrites, only direct file paths will work; `__data.json` will return 404 because it is not mapped to `__data.php`.
- Vhost rule set copied verbatim from `build/.htaccess` (php-static):

```apache
<IfModule mod_rewrite.c>

    RewriteEngine On

    # 1. Serve static files if they exist
    RewriteCond %{REQUEST_FILENAME} -f
    RewriteRule ^ - [L]

    # 2. SvelteKit __data.json Bridge
    # Rewrite /path/__data.json -> /path/__data.php
    RewriteRule ^(.*)/__data\.json$ $1/__data.php [L]

    # 3. Handle Prerendered HTML / PHP
    # If request is /foo, check for /foo.php (prerendered)
    RewriteCond %{REQUEST_FILENAME}.php -f
    RewriteRule ^(.*)$ $1.php [L]

    # 4. Fallback to index.php (SPA / Dynamic)
    RewriteCond %{REQUEST_FILENAME} !-f
    RewriteRule ^ index.php [L]
</IfModule>
```

- Checklist for routing to work:
  - `__data.json` requests must map to `__data.php`.
  - Extensionless routes must resolve to their prerendered `.php` files.
  - Remaining routes must fallback to root `index.php`.
- Query string and `PATH_INFO` handling are not explicit in `build/.htaccess`. There is no `[QSA]` flag and no `PATH_INFO` rule, so behavior depends on Apache defaults and the PHP handler. **Inference:** if you need guaranteed query-string preservation under unusual vhost setups, mirror Apache’s default behavior or add an explicit `QSA` flag after validating it against your host.

## 5. Adapter Config Options

### Build-time options (`adapter/src/index.ts`)

- mode: `php-static` or `node-ssr` (default `php-static`), selects output type and routing behavior.
- ssr: boolean (default `true`), controls HTML-to-PHP conversion and hydration injections.
- out: output directory (default `./build`).
- assets: client asset output directory (default `./build`).
- precompress: boolean (default `false`), enables `.br/.gz` handling in `.htaccess`.
- fallback: boolean (default `false`), affects prerender safety behavior.
- strict: boolean (default `true`), enforces prerender-only routes in php-static (unless disabled).

Evidence: adapter/src/index.ts:L12-L21, adapter/src/types.ts:L1-L10

### Build config wiring (`svelte.config.js`)

- ADAPTER_MODE: maps to `mode`.
- BASE_PATH: maps to `kit.paths.base`.
- PRECOMPRESS: maps to `precompress`.

Evidence: svelte.config.js:L4-L28

### Runtime env options

- SK_BASE_PATH: read by `__data.php` and `router.php` to adjust routing and stripping.
- SIDECAR_HOST, SIDECAR_PORT, ALLOW_NONLOCAL_SIDECAR: control Node sidecar proxying in `node-ssr`.
- PROXY_TIMEOUT_MS, PROXY_CONNECT_TIMEOUT_MS, MAX_BODY_BYTES: proxy timeout/body limits for `node-ssr`.
- PORT: sidecar port for `server/handler.mjs`.

### Footguns

- Base path mismatch breaks asset and route URLs; rebuild with correct `BASE_PATH`.
- Disabling rewrites yields HTML for `__data.json`, breaking client navigation.
- `node-ssr` requires a running sidecar; otherwise `index.php` returns 502.
- `precompress=true` requires precompressed `.br/.gz` assets and correct `mod_headers/mod_mime` handling.

## 7. Securing `_protected/`

- `_protected/` must not be web-accessible because it contains server-side PHP logic.
- The PHP built-in router blocks `_protected/` directly.
- The current build `.htaccess` does not include a rule that denies `_protected/`.

Primary recommendation (Apache 2.4+):

```apache
# /_protected/.htaccess
Require all denied
```

Alternative (vhost-level, Apache 2.4+):

```apache
<Directory "/var/www/html/_protected">
    Require all denied
</Directory>
```

Optional defense-in-depth (rewrite rule):

```apache
RewriteRule ^_protected/ - [F]
```
